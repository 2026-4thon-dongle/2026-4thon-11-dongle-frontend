- 7-12 프로필 원의 그림: 닉네임별 그림이 없어서 목록 순서대로 돌려 쓴다.

## 시안에 없어서 임의로 정한 것

- 7-3: 삭제 확인 화면이 없다. 휴지통을 누르면 바로 삭제하고 토스트("임시저장한 편지를 삭제했어요")만 보여 준다. 빈 목록 화면이 없다. 안내 박스만 남는다.
- 7-12: 해제 확인 화면이 없다. "해제"를 누르면 바로 해제하고 토스트("차단을 해제했어요")를 보여 준다. 빈 목록 화면이 없다.
- 7-13: 로그아웃 확인 화면이 없다. 바로 실행하고 토스트("로그아웃했어요") 뒤 `/start`로 이동한다. 탈퇴 뒤에도 토스트("탈퇴 처리했어요") 뒤 `/start`로 이동한다.
- 7-9: 오류 문구("2~10자로 입력해주세요", "이미 사용 중인 닉네임이에요")와 저장 토스트("닉네임을 바꿨어요"). 저장하면 `/mypage`로 이동한다. 바뀐 게 없거나 사용할 수 없으면 저장 버튼을 누를 수 없다.
- 7-10: 지역을 고르는 시트(공용 `RegionPicker`)가 시안에 없다. 저장 토스트("지역을 바꿨어요")와 저장 뒤 `/mypage` 이동을 정했다. "+ 다시 칠하기"는 동작 없이 토스트("아직 준비 중이에요")만 보여 준다.
- 7-11: 시안의 안내 문구는 "푸시"이고 프레임 이름은 "이메일"이다. 화면에 보이는 글자(푸시)를 따랐다. 스위치끼리 서로 영향을 주지 않는다. 누르면 화면을 먼저 바꾸고 저장하며, 실패하면 되돌린다.
- 7-1: 설정 아이콘의 도착 화면(`/mypage/settings`)이 시안에 없다. "알림 · 편지 쉬기" 줄의 값은 모아 받기가 켜져 있을 때만 "하루 한 번"이고, 꺼져 있을 때의 문구는 정하지 않아 비워 둔다.
- 7-4~7-6: 우표는 보유한 것을 앞에 두고 나머지는 원래 순서로 둔다. 실제 정렬 규칙은 모른다. 줄 간격은 시안대로 탭마다 따로 적용했다(7-4 17px, 7-5 25px). 7-5(꾸미기) 탭의 아래 버튼은 시안이 없어서 업적 탭과 같은 "보상 모아보기"로 뒀다. 7-6의 버튼은 `/diary/write`로 가정했다.
- 7-7: 잠긴 우표는 누를 수 없다(잠긴 우표를 눌렀을 때 화면이 시안에 없다).
- 7-8: 보상 미리보기 그림 4종(편지지 「밤하늘」 등)은 원본 에셋이 없어서 CSS로 비슷하게 그렸다. 보상 카드를 눌러도 동작이 없다.
- 7-1, 7-3~7-13 전체: 로딩 실패·오류 화면이 없다. 로딩 중에는 `Skeleton`만 보여 주고, mock이 실패할 일이 없어서 오류 처리를 만들지 않았다. 실제 API를 연결할 때 `ErrorBoundary`에 맡길지 화면별로 처리할지 정해야 한다.

## 확인이 필요한 것

**디자이너**

1. 7-6(우표 0개)을 어떤 상황에서 보여 줄지. 가입하면 「첫 걸음」 우표를 받으므로 정상 사용자에게는 거의 나올 수 없다.
2. 7-3(임시저장)과 7-12(차단) 빈 목록 화면, 7-3 삭제와 7-12 해제의 확인 화면 필요 여부.
3. 7-1의 설정 아이콘이 여는 화면, 그리고 거기서 7-9(닉네임), 7-12(차단), 7-13(로그아웃·탈퇴)으로 들어가는 길.
4. 우표 개수가 시안 안에서 어긋난 것(7-4 5개 vs 7-7·7-8 6개), 7-1 "5 / 17"의 17의 뜻, 7-5와 7-4의 보상 개수 기준.
5. 7-11의 "푸시"와 "이메일" 중 맞는 표기.
6. 잠긴 우표를 눌렀을 때, 지역 선택 시트, 7-1 통계 0일 때, 오류·로딩 실패의 시안.
7. 7-8 보상 미리보기 그림 원본 에셋.

**효령님**

1. 7-1 "내 일기"가 `/diary/mine`으로 가는 것이 맞는지, 7-6 버튼의 `/diary/write`가 맞는지.
2. 7-13 로그아웃·탈퇴 뒤 `/start`로 보내는 것이 맞는지. 실제 로그아웃 시 토큰 삭제와 로그인 상태 처리는 로그인 쪽과 겹치므로 어디서 맡을지.
3. 7-12 차단 목록과 3-6~3-8 신고·차단의 데이터 형태(`api/safety.md` 기준)가 같은지.
4. 7-6이 실제로 나올 수 있는 상태인지(가입 시 첫 걸음 우표 지급과 관련).

**채현님**

1. 임시저장 이어 쓰기: 7-3이 넘기는 `letterId`를 편지 쓰기가 읽어야 하는지, 그리고 임시저장 본문을 복원하는 방법(저장 방식 미정). 지금은 본문을 복원하지 못한다.
2. 7-7이 넘기는 `stampId` 쿼리를 편지 쓰기가 읽어 우표를 미리 고르게 할지.
3. 우표 mock(`shared/mocks/stamps.js`)의 id·이름·종류를 우표 선택(4-6, 4-7)과 우표첩이 계속 같이 쓰는지. `owned` 값은 우표첩에서 쓰지 않는다.

**백엔드**

1. 우표 목록·보유 상태·수집 보상·우표 상세 API가 필요한지(현재 `granted_stamps`만 있다). 문서 레포 `requests/`(`fe2be`) 작성 대상이다.
2. 임시저장 목록·삭제 API와 `GET /api/users/me/`의 `draft_count`.
3. `GET /api/users/me/`의 `school_name`, 우표 총 개수(`stamp_total`).
4. 알림 설정의 "편지 도착", "편지가 출발했을 때" 필드 여부. 현재 `settings` 명세에 없다.
5. 7-12 차단 카드에 지역을 줄지(`GET /api/blocks/` 응답).
6. 가입 시 「첫 걸음」 우표가 항상 지급되는지.
