## 확인 방법

`npm run dev`로 실행한 개발 환경에서만 인증 UI 데모를 제공한다.
ac.kr 학교 이메일 형식의 임의 주소와 테스트 코드 **472913**으로 진행한다.
실제 이메일 발송, 계정 생성, 로그인 세션 생성, 서버 저장은 하지 않는다.
데모 로그인 인증 성공 후 `/home`으로 이동하며, 같은 브라우저에 저장된 가입 프로필을 사용한다.
코드는 5분 유효하며 재요청 간격은 30초, 잘못 입력할 수 있는 횟수는 5회다.
가입 도중 입력값과 데모 인증 상태는 새로고침하면 초기화된다.
가입 완료 후 닉네임·본가·거주지·로컬 사용자 ID는 브라우저에 저장해 완료 화면과 홈에서 공유한다.
지역 선택의 시·도 및 시·군·구 목록은 가나다순으로 정렬한다.

운영 빌드에서는 데모 인증이 비활성화되어 코드 요청 시 서버 미연결 안내를 표시한다.
`shared/api/auth.js`의 requestCode, verifyCode, completeSignup를 실제 인증 서버와 연결해야 한다.
닉네임 중복 확인·실명 정책 검증, 지역별 공식 ID 및 상세 행정구역은
서버/기획 데이터 연동이 필요하다. 약관은 사용자가 제공한 2026-11-09 데모용 초안을
`components/signup/terms.js`에 보관하며 필수 3항목·선택 1항목 모두 전문을 열 수 있다.
팝업 열람은 체크 상태를 변경하지 않으며 선택 동의 없이도 다음 단계로 이동할 수 있다.
약관 버전·동의 일시의 서버 저장은 인증 서버 연동 시 추가해야 한다.
지역 목록은 디자인 확인용으로, 도 지역의 거주지는 시·군 수준이며 세부 구 분할은
지역 API 연결 시 확장해야 한다.

## 공용 모듈

- `shared/ui/AuthFrame`: 가입·인증 헤더, 진행 표시, 하단 버튼 영역.
- `shared/ui/CodeVerification`: 숫자 입력·붙여넣기·자동 포커스 이동, 오류·타이머·재요청.
- `shared/region/RegionPicker`: 본가 복수 선택·삭제, 거주지 단일 선택.
  본가는 서울·부산·대구·인천·광주·대전·울산·세종을 즉시 선택하며, 도 지역은
  시·군까지 선택해야 한 칸을 차지한다. 세 곳을 채우면 선택하지 않은 칩을 비활성화한다.
  선택한 도는 하위 시·군 해제를 위해 열 수 있고, 이미 선택된 칩과 삭제 버튼은 유지한다.
  시·도 목록 아래 구분선은 상세 목록 표시 여부와 관계없이 항상 보인다.
- `shared/ui/Mascot`, `shared/ui/Icon`: 기존 팀 공유 마스코트·아이콘을 재사용한다.
- `shared/assets/decorations`, `shared/assets/stamps`: 기존 공유 에셋에 없는 장식·우표만 보관한다.
- `components/intro/IntroIllustration`: 소개 화면 전용 장식·우표 조합. 전체 에셋 glob 대신 필요한 파일만 명시적으로 import한다.
- `shared/mocks/auth`: 인증 데모 데이터·동작. 화면은 `shared/api/auth` 경계만 사용한다.

## 지침 점검 및 남은 연동

`CLAUDE.md`와 `docs/ownership.md`의 현재 화면 번호(1-1~1-12) 및 담당 폴더를 따른다.
페이지는 `pages/intro`, `pages/signup`, `pages/login`, 기능 전용 컴포넌트는 같은 기능의
`components` 폴더, 두 기능 이상에서 사용하는 인증 UI와 지역 선택은 `shared`에 둔다.
다른 담당자의 기능 페이지·전용 컴포넌트는 import하거나 수정하지 않는다.

2026-11-09 로컬 점검 시 지침의 `../2026-4thon-11-dongle-documents`가 존재하지 않아
`api/`·`spec/`와의 대조는 수행하지 못했다. 문서 레포를 연결한 뒤 명세 대조가 필요하다.
현재 인증 정책과 완료 안내는 개발용 미리보기이며 확정된 서버 명세로 간주하지 않는다.

공용 Overlay·Loading·ErrorBoundary가 현재 저장소에 없어 약관 보기는 임시 native dialog를
사용한다. 공용 모듈이 제공되면 교체해야 한다. `shared` 추가·수정은 팀 공지와 PR 리뷰 대상이며,
이 로컬 작업에서 PR 생성·팀 메시지 전송·머지는 수행하지 않았다. PR 작성 시 관련 명세 경로를
적고, 미연결 상태인 항목을 함께 표시해야 한다.
