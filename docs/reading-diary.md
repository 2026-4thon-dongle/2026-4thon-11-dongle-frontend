## 구현과 공용 변경

- 화면은 `pages/home`, `pages/diary`, `pages/notification`으로 분리한다.
- 기능 전용 컴포넌트는 `components/home`, `components/diary`에 둔다.
- 공용 Button·Chip·Header·Mascot·Icon·Stamp·Overlay를 재사용한다.
- 홈과 상세에서 공유하는 엽서 사진·우표·소인 조합은 `shared/ui/DiaryPostcardParts`에 추가한다.
- 기존 공용 원본 에셋을 유지하며, 공유 에셋에 없는 일러스트·소인·장식 8개만
  `shared/assets/reading`에 추가한다. 임시 Figma URL을 런타임에 사용하지 않는다.
- `shared/api/readingDiary`, `shared/mocks/readingDiary`, `shared/hooks/useReadingDiary`는
  피드·상세·알림에서 숨김·차단·읽음 상태를 함께 사용하기 위한 경계다.
- 라우트는 `app/routes/authRoutes.jsx`에 연결한다. 공용 TabBarLayout의 로딩·에러 경계를 사용한다.
- 최대 너비 430px, 좌우 20px, 피드 100%·2열 grid와 가로 스크롤 필터를 적용한다.

## 연동 필요

- 01 가입 프로필, 02 첫 일기, 06 일기 저장소와 연결했다. 로컬 일기 변경은 피드·상세에 즉시 반영한다.
  내 글은 홈 피드에서 제외하며 `/diary/mine`에서 확인한다.
- 현재 사용자 `다인`과 본가 천안·아산·대전, 일기·사진 일러스트·알림·배송 시간은 개발용 예시다.
  실제 로그인 사용자, 지역, 일기 목록·상세·사진·알림 API로 교체해야 한다.
- 데모는 개발 모드에서만 제공한다. 운영 빌드는 API 미연결 안내를 표시한다.
- 신고는 해당 일기를 내 화면에서 숨기고, 차단은 해당 작성자의 일기·관련 알림을 데모 상태에서 제외한다.
  이 변경은 메모리 상태라 새로고침 시 초기화된다. 실제 신고 접수·차단 저장은 하지 않는다.
- 신고 3건에 따른 전체 숨김, 운영진 검토, 쌍방 편지 차단은 서버가 보장해야 한다.
  현재 다른 담당자의 편지·차단 설정 기능을 수정하지 않았으며 서버 정책을 구현한 것으로 간주하면 안 된다.
- 알림 읽음 처리는 메모리에서만 반영한다. 저녁 8시 이메일 발송은 구현하지 않는다.
- 알림의 우체통·배송·우표첩, 일기 작성·배달 게임은 기존 경로로 연결한다.
  아직 placeholder인 목적 화면과 최종 URL 계약은 각 담당자와 확인해야 한다.

## 편지 답장 계약

기존 편지 작성 Provider가 이미 읽는 쿼리 이름을 그대로 사용한다.

```text
/letter-write/paper?diaryId=sky-lake&nickname=하늘빛&region=충남 천안
```

실제 URL은 `URLSearchParams`로 인코딩하며 상세와 카드에서 동일한 함수를 사용한다.
`useStartLetter()`와 4-9 임시저장 시트가 아직 없어 직접 링크를 유지한다. 훅이 제공되면 두 진입점을 교체해야 한다.
편지 담당자의 페이지·전용 컴포넌트는 import하거나 수정하지 않는다.
