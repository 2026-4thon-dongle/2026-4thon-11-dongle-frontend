# 담당 분배표

담당은 팀원 이름으로 표시한다. 화면 번호는 Figma 시안의 `섹션-순번`이다. 소스 폴더 이름에는 담당자 이름을 쓰지 않고 기능 이름을 쓴다.

| 담당 | 섹션 | 화면 번호 | 폴더 |
|---|---|---|---|
| 효령 | 01 첫 실행·가입 | 1-1~1-12 | `src/pages/intro`, `signup`, `login` |
| 효령 | 02 첫 고향 일기 | 2-1~2-3 | `src/pages/diary` |
| 효령 | 03 고향 일기 읽기 | 3-1~3-8 | `src/pages/home`, `notification`, `diary` |
| 효령 | 06 내 동네 일기 쓰기·관리 | 6-1~6-7 | `src/pages/diary` |
| 채현 | 04 편지로 답장하기 | 4-1~4-12 | `src/pages/letter-write`, `delivery` |
| 채현 | 08 공통 상태 | 8-1~8-2 | `src/shared/feedback` |
| 채현 | 공용 컴포넌트와 기반 모듈 | - | `src/shared` |
| 채원 | 05 우체통·편지 받기 | 5-1~5-15 | `src/pages/mailbox`, `pen-pal` |
| 채원 | 07 마이·우표첩 | 7-1~7-13 | `src/pages/mypage` |
| 미배정 | 09 보류·후보 | 9-1~9-4 | `src/pages/delivery-game`, `stamp-make` (후보) |

- 09는 구현 여부가 정해지지 않았다. 구현하기로 하면 담당을 정한다.
- 02, 03, 06은 모두 효령 담당이며 `diary` 폴더를 함께 쓴다. 화면 번호별 세부 매핑은 `CLAUDE.md`의 「화면 → 폴더 매핑」을 따른다.

## 컴포넌트 배치

- 화면 전용 컴포넌트는 `src/components/<기능명>`에 둔다.
- 여러 기능에서 함께 쓰는 컴포넌트와 데이터는 `src/shared`에 둔다.
- 각 화면은 자신의 기능 컴포넌트와 `src/shared`만 사용하고, 다른 기능의 화면·전용 컴포넌트를 직접 import하지 않는다.
- 담당과 실제 코드 경로는 분리해 관리한다. 다른 담당 기능이나 `shared`를 수정할 필요가 있으면 작업 전에 팀에 알리고 합의한다.

## 기능 간 연결 합의

- 지역 선택: 가입(효령), 편지 받을 지역(채현), 지역 설정 수정(채원)은 모두 `src/shared/region`을 사용한다.
- 일기에서 편지 보내기: 효령의 일기 상세(3-5)에서 채현의 편지 작성(4-1)으로 이동할 때 일기 ID, 상대 닉네임, 지역을 URL 파라미터로 전달한다.
- 우체통에서 답장하기: 채원의 답장 화면(5-10, 5-11)이 채현의 편지 작성과 어떻게 연결되는지는 두 사람이 합의해 이 절에 기록한다. 연결 시 위와 같은 URL 파라미터 규칙을 쓴다.
- 우표: 채현의 우표 선택(4-6, 4-7)과 채원의 우표첩(7-4~7-8)은 `src/shared/mocks`의 동일한 데이터 형태를 사용한다.
- 신고·차단: 효령의 신고·차단 UI(3-6~3-8)와 채원의 차단 목록(7-12)은 공통 데이터 형태를 사용한다.
