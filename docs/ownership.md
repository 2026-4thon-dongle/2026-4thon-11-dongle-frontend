# 담당 분배표

A/B/C는 팀원별 담당을 표시하는 구분자이며, 소스 폴더 이름에는 사용하지 않는다. 화면과 컴포넌트는 기능 이름으로 관리한다.

| 담당 | 담당 기능·화면 | 폴더 |
|---|---|---|
| A | 인트로(0-1~0-3), 가입(1-1~1-10), 로그인(1-11), 홈(2-1~2-3), 알림(2-4), 일기(2-5~2-15) | `src/pages/intro`, `signup`, `login`, `home`, `notification`, `diary` |
| B | 편지 쓰기(3-1~3-12), 배송(3-13~3-15·3-17), 직접 배달하기(3-16), 우표 만들기(3-18) | `src/pages/letter-write`, `delivery`, `delivery-game`, `stamp-make` |
| C | 우체통(4-1~4-9), 펜팔 친구(4-11~4-12), 마이페이지(5-1~5-10) | `src/pages/mailbox`, `pen-pal`, `mypage` |
| 공통 | 로딩·에러 상태(06), 공용 UI와 기반 모듈 | `src/shared` |

## 컴포넌트 배치

- 화면 전용 컴포넌트는 `src/components/<기능명>`에 둔다.
- 여러 기능에서 함께 쓰는 컴포넌트와 데이터는 `src/shared`에 둔다.
- 각 화면은 자신의 기능 컴포넌트와 `src/shared`만 사용하고, 다른 기능의 화면·전용 컴포넌트를 직접 import하지 않는다.
- 담당과 실제 코드 경로는 분리해 관리한다. 다른 담당 기능이나 `shared`를 수정할 필요가 있으면 작업 전에 팀에 알리고 합의한다.

## 기능 간 연결 합의

- 지역 선택: 가입(A), 편지 받을 지역(B), 지역 수정(C)은 모두 `src/shared/region`을 사용한다.
- 일기에서 편지 보내기: A의 일기 상세에서 B의 편지 작성으로 이동할 때 일기 ID, 상대 닉네임, 지역을 URL 파라미터로 전달한다.
- 우체통에서 답장하기: C의 답장 화면에서 B의 편지 작성으로 이동하며 동일한 URL 파라미터 규칙을 사용한다.
- 우표: B의 우표 만들기와 C의 우표첩은 `src/shared/mocks`의 동일한 데이터 형태를 사용한다.
- 신고·차단: A의 신고 UI와 C의 차단 목록은 공통 데이터 형태를 사용한다.
