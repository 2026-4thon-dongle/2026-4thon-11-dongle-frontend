공개 범위는 저장 버튼을 눌러야 반영되며 닫기·Escape는 변경을 취소한다.

## 구현 구조

- 화면·경로: `pages/diary/OwnedDiaryWorkspace`, 지연 로딩: `OwnedDiaryRoute`.
- 기능 전용 UI: `components/diary/OwnedDiary*`, Overlay 포커스 훅.
- 일기 API 경계: `shared/api/ownedDiary.js`.
- 예시 데이터: `shared/mocks/ownedDiary.js`, 상태 구독: `shared/hooks/useOwnedDiaries.js`.
- 기존 Header·Chip·Button·Icon·Mascot·Stamp·Overlay·Toast와 공용 라우트의 로딩·에러 처리를 재사용한다.
- 공용 에셋 원본은 수정하지 않고, 없는 지역 기본 이미지·배경·소인 8개만 기능 전용 assets에 추가한다.
- 최대 430px, 좌우 20px, 폼·버튼 100%, 목록 2열 grid로 구현한다.

## 추후 연동·PR 참고

- 현재 브랜치 `feature/20-writingdiary-ui`에 01·02·03 작업이 없어 해당 페이지와 데이터 저장소를 수정하지 않았다.
  통합 시 03의 `/diary/write` placeholder를 이번 작성 라우트로 교체해야 한다.
- 마이페이지 담당 화면에서 내 일기 목록을 `/diary/mine`으로 연결할 수 있다. 마이페이지 구현은 이번 범위에 없다.
- 닉네임·작성 지역·기존 일기·사진은 개발용 예시다. 실제 가입 사용자 및 거주 지역으로 교체해야 한다.
- `shared/api/ownedDiary`의 생성·수정·삭제·공개 범위 함수를 실제 서버와 연결해야 한다.
  사진 업로드, 작성자 권한 검사, 요청 중복 방지, 실패 처리, 공개 범위·편지 받기의 서버 정책도 필요하다.
- 현재 편지 받기·공개 범위는 개발용 내 일기에만 반영된다. 타인 피드와 편지 버튼 표시·접근 제한은
  03 피드 및 편지 기능과 서버 데이터를 통합한 뒤 연결해야 한다.
- 개발 모드에서만 예시 데이터를 제공한다. 운영 빌드는 API 미연결 안내를 표시한다.
- 작성 중 초안과 생성·수정·삭제 결과는 메모리 상태다. 페이지를 벗어나면 저장 전 초안은 사라지고,
  새로고침하면 예시 데이터로 초기화된다. 실제 서버 저장·게시·우표 지급은 수행하지 않는다.
- 목록 개수는 실제 개발용 항목 수로 계산한다(초기 4편 → 예시 일기 삭제 시 3편).
  피그마의 11편은 전체 목록 API 응답이 연결되면 실제 개수로 표시해야 한다.
- 업로드 미리보기 URL은 교체·삭제·화면 종료 시 해제한다. 저장된 개발용 사진 URL은 교체·삭제 시 해제한다.
